# 🔒 SECURITY & COMPLIANCE: Legal + Technical Security

## Legal Compliance Framework

### Opt-In Only Principle

**Core Rule:** All contacts in Notion = explicit consent obtained

```
What counts as "consent":
  ✅ Written email: "Can we contact you about services?"
  ✅ Phone call: "May I send you information?"
  ✅ Website form: "Subscribe to updates"
  ✅ LinkedIn: Private message "interested in chat?"
  
What does NOT count:
  ❌ Scraping random phone numbers from internet
  ❌ Buying contact lists from brokers
  ❌ Sending to blocklists (competitors, opt-out lists)
  ❌ Cold contacting without prior interaction
```

**Implementation:**
- User manually adds contacts to Notion
- No automatic scraping/importing
- Task: User maintains "is_opted_in" field in Notion
- Before sending: Check is_opted_in = true

### Personalization Requirement

**Rule:** Each message must be unique, not a template

```
Template (WRONG):
  "Привет! Хотите увеличить продажи? Пишите в ответ."
  [Sent to 1000 contacts identically]

Personalized (CORRECT):
  "Иван, видел что ООО ТДБаза работает 5 лет. 
   Есть идея как автоматизировать процессы."
  [Different for each lead, generated by Gemini]
```

**Implementation:**
- Gemini generates unique message per lead (using company data)
- Each message includes specific company name/detail
- Same structure, different content
- Notion field: message_unique_id (track uniqueness)

### Business Hours Only

**Rule:** Send messages during business hours only (9:00-21:00 MSK)

```
Enforcement:
  Before sending task:
    • Get current time
    • If time < 09:00 or time > 21:00:
      - Queue task for 09:00 tomorrow
      - Don't send now
    • If 09:00-21:00: Send normally

Reason:
  • Avoids bot detection (bots send 24/7)
  • Respectful (don't spam at 3 AM)
  • Better response rates (people awake)
```

**Implementation:**
```
Python code:
  from datetime import datetime
  import pytz
  
  msk = pytz.timezone('Europe/Moscow')
  now = datetime.now(msk).time()
  
  if now < time(9, 0) or now > time(21, 0):
    # Queue for 09:00
    task.scheduled_time = tomorrow_09_00
    task.status = "scheduled"
  else:
    # Send now
    execute_task(task)
```

## Anti-Fraud Detection Avoidance

### What Triggers Bot Detection?

#### Pattern 1: Repetitive Content

```
❌ DETECTED AS BOT:
  Message 1: "Привет, помочь вам?"
  Message 2: "Привет, помочь вам?" [10 sec later]
  Message 3: "Привет, помочь вам?" [10 sec later]
  → RED FLAG: Identical messages = mass bot

✅ AVOIDS DETECTION:
  Message 1: "Иван, видел выручка ООО ТДБаза 7млн..."
  Message 2: "Александр, интересно как работает ФГБУ..."
  Message 3: "Мария, развиваетесь в сфере логистики..."
  → Each unique = real human
```

**Implementation:**
- Gemini generates unique message per lead (confidence > 70%)
- If confidence < 50%: Use personalized template (still different per lead)
- Compare message hashes: No exact duplicates allowed

#### Pattern 2: Too Fast Sending

```
❌ DETECTED AS BOT:
  Send message → wait 0.5 sec → next message
  → RED FLAG: Robotic speed

✅ AVOIDS DETECTION:
  Send message → wait 5-60 seconds (random) → next message
  → Looks human
```

**Implementation:**
- Rate limits: Max 10 messages/hour per device
- = Minimum 6 minutes between messages
- Plus HumanBehavior delays (60-70 sec per send)
- = Natural 6-10 minute intervals

#### Pattern 3: Same Sender Multiple Accounts

```
❌ DETECTED AS BOT:
  Same MAC address controlling 100 devices
  → RED FLAG: Coordinated spam campaign

✅ AVOIDS DETECTION:
  20 separate SIM cards, separate phone numbers
  Different MAC addresses (different devices)
  Spread across multiple platforms
  → Looks like real team
```

**Implementation:**
- Each of 20 devices: Different phone number
- Different SIM cards (corporate plan)
- Different app accounts on each device
- Not all sending at same time (staggered)

#### Pattern 4: Account Age Too New

```
❌ DETECTED AS BOT:
  New account created today → sends 50 messages today
  → RED FLAG: Obvious spam bot

✅ AVOIDS DETECTION:
  Account created 7 days ago → Day 1-3: warmup (0 sends)
  → Day 4-7: gradual ramp (1-5 messages/day)
  → Day 8+: normal pace (30 messages/day)
  → Looks like legitimate account
```

**Implementation:**
- Warmup period: Track device_created_date
- Ramp-up schedule:
  ```
  Days 1-3: 0 messages (just app interaction)
  Days 4-5: 1-2 messages
  Days 6-7: 3-5 messages
  Day 8+: up to 30 messages/day
  ```

#### Pattern 5: Suspicious Keywords

```
❌ DETECTED AS BOT (spam keywords):
  "Заработай 100k за месяц!"
  "Лото, розыгрыш, подарок!"
  "Кредит за 5 минут!"
  → RED FLAG: Classic spam

✅ AVOIDS DETECTION:
  "Видел выручку вашей компании, есть идея"
  "Помощь с автоматизацией процессов"
  "Когда удобно обсудить детали?"
  → Legitimate B2B communication
```

**Implementation:**
- Gemini generates message (designed for B2B, not spam)
- Content filter: Block common spam keywords
- Manual review: User can preview before sending

## Technical Security

### API Key Management

```
File: .env (local, never in git)
Format:
  NOTION_API_KEY=ntn_123456789...
  GEMINI_API_KEY=AIza...
  TELEGRAM_BOT_TOKEN=123456789:ABCDEF...

Access Control:
  • Backend process reads .env on startup
  • Keys loaded into environment variables
  • Keys never logged or exposed
  • Frontend has NO access to API keys
  
If key compromised:
  1. User creates new key in service admin panel
  2. Update .env file
  3. Restart backend
  4. Revoke old key (if supported by service)
```

### Database Security

```
SQLite (Local, Unencrypted):
  • File: /data/database.db
  • Permissions: chmod 600 (owner only)
  • No encryption (local file, not exposed)
  • Backup: cp database.db database_backup.db
  
Sensitive data in DB:
  • API keys: NO (in .env, not in DB)
  • Phone numbers: YES (from Notion CRM)
  • Company data: YES (public info)
  • Messages: YES (audit trail)
  
Protection:
  • Local file only (no network access)
  • Filesystem permissions (user:group access)
  • Automated backups (daily)
  • Encrypted backups (tar + gpg, optional)
```

### Network Security

```
Frontend ← → Backend: HTTP (local only)
  • localhost:3000 ← → localhost:8000
  • Not exposed to internet
  • No HTTPS needed (local machine)
  • WebSocket for realtime updates

Backend → External APIs: HTTPS (secure)
  • Notion API: HTTPS + API key auth
  • Gemini API: HTTPS + API key auth
  • Telegram API: HTTPS + token auth
  • All requests over secure channels

Device ← → Backend: USB (local only)
  • ADB protocol over USB 3.0
  • No network exposure
  • Encrypted: Not needed (local)
  • Timeout: 5 sec (protect from hangs)
```

### Device Security

```
Physical Security:
  • Devices in locked cabinet (optional)
  • USB cables tied down (prevent loose connections)
  • SIM cards slot-protected (can't remove while running)
  
Software Security:
  • No rooting (use stock Android)
  • No custom ROMs (may have vulnerabilities)
  • Factory reset on hardware failure (wipe all data)
  • Auto-lock after 5 min inactivity (screen lock)

Credentials on Device:
  • MAX account: Fresh account (no personal data)
  • WhatsApp account: Fresh SIM (no backup data)
  • SMS: Native, no login needed
  • No backup to cloud (Photos, Contacts, etc)
  • No Google account sync (prevent data leaks)
```

## Rate Limits & Compliance

### SMS Operator Limits (Enforced by Provider)

```
Corporate SMS Plan (typical):
  • Max 1000 SMS/day per SIM
  • Max 100 SMS/hour per SIM
  • Max 10 SMS/min per SIM
  • Cost: ~1-2 RUB per SMS
  
System enforcement:
  • Per device per hour: max 10 SMS
  • Per device per day: max 40 SMS
  • Below provider limits (safe margin)
  
Buffer:
  • Configured: 40/day
  • Provider limit: 1000/day
  • Safety margin: 25× (plenty)
```

### MAX App Limits (Reverse-Engineered)

```
Estimate (from Part 3 research):
  • Max 10 messages/hour per account
  • Max 30 messages/day per account
  • Longer inactive = higher limit
  
System enforcement:
  • Per device per hour: max 10
  • Per device per day: max 30
  • At provider's limit (balanced)
  
Detection systems:
  • Same message to multiple users = instant ban
  • Rapid fire sends = warning
  • New account sending 50/day = block
  
How we avoid:
  • Unique message per user (Gemini)
  • 6 min gaps between sends
  • Gradual ramp-up (day 1-3 warmup)
  • HumanBehavior (realistic delays)
```

### WhatsApp Limits (Official Documented)

```
Business API limits:
  • Max 1000 messages/day per account (official)
  • Max 60 messages/minute (API rate limit)
  • New account: May have lower initial limits
  
System enforcement:
  • Per device per hour: max 10
  • Per device per day: max 30
  • Well below official limits (safe)
  
Additional:
  • Must use Official WhatsApp Business API (not app)
  • Message templates (for business messages)
  • Opt-in message category (not promotional)
  
Current approach:
  • Using WhatsApp app + UIAutomator (not official API)
  • Not using message templates
  • May trigger rate limiting faster
  
Future upgrade:
  • Integrate Official WhatsApp Business API
  • Use message templates
  • Increase limits to 1000/day
```

## Data Privacy & GDPR

### Data Minimization

```
Collect only what needed:
  ✅ Name (for personalization)
  ✅ Phone (to send message)
  ✅ Company (for context)
  ✅ Revenue/profit (public, from RusProfile)
  
Don't collect:
  ❌ Personal email
  ❌ Home address
  ❌ Family data
  ❌ Financial data beyond public revenue
```

### Right to be Forgotten

```
If contact asks to opt-out:
  1. User removes from Notion CRM
  2. System won't send further messages
  3. Old messages: Log retained (for audit)
  4. Never send to this number again
  
Implementation:
  • Add blocklist table (opt_out_numbers)
  • Before sending: Check if in blocklist
  • If yes: Reject task
```

### Transparency

```
Message should indicate:
  • Who is sending (your company name)
  • Why (brief: "sales inquiry")
  • How to opt-out (reply "STOP")
  
Example message:
  "Иван, это Иван из Company XYZ.
   Видел что ООО ТДБаза работает в сфере...
   Есть идея как помочь. Если не интересно, напишите STOP."
```

### Data Retention

```
Keep data for:
  • 30 days: Execution logs (technical debugging)
  • 30 days: Screenshots (audit trail)
  • Forever: Task metadata (business record)
  • Forever: Contact records (in Notion, not our DB)
  
Delete:
  • Log files older than 30 days
  • Screenshots older than 7 days
  • Never delete core task records (audit)
```

## Incident Response Plan

### Data Breach (if API key exposed)

```
1. Immediate (< 1 hour):
   • Revoke compromised API key
   • Update .env with new key
   • Restart backend
   
2. Same day:
   • Rotate all other keys (Gemini, Notion, Telegram)
   • Check logs for unauthorized access
   
3. Next day:
   • Review audit logs
   • Check for suspicious activity
   • Update security documentation
```

### Account Ban (if device/SIM blocked)

```
1. Immediate:
   • Stop sending from this device
   • Switch to different device for same contacts
   • Re-queue task (if needed)
   
2. Next few hours:
   • Wait for platform review (usually lifts in 24 hours)
   • Try manual verification (if allowed)
   
3. If permanent ban:
   • Device is lost (mark as broken)
   • Order replacement device + SIM
   • Re-enable when ready
```

### System Compromise (malware, unauthorized access)

```
Very unlikely (local system, no cloud exposure):
  But if it happens:
  
1. Disconnect all USB cables (isolate)
2. Don't access any APIs (prevent further damage)
3. Run antivirus scan on Mac
4. If compromised: Format + reinstall OS
5. Re-setup system from scratch
```
